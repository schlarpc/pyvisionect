# `pyvisionect.imaging`

The whole pixel pipeline for a Visionect e-ink sign. Pure functions; no sockets, no
clock, no global state. Needs only **numpy** and **Pillow** (`pip install
pyvisionect[imaging]`).

```python
from pyvisionect.devices import panel_for
from pyvisionect.imaging import Dithering, encode_frame

frame = encode_frame(
    pil_image,                        # 1440x2560 for the 32" sign
    panel=panel_for(display_type),    # or imaging.PANEL_32INCH
    encoding=4,                       # 4 bpp / 16 greys
    dithering=Dithering.BLUE_NOISE,
)
# frame.rectangles  -> list[EncodedRect]: x, y, w, h, screen_id, options, data
# frame.state_checksum -> ImageHeader.Checksum
# frame.state       -> pass back as prev_state next time
```

## Why the library owns all of this

The device does **waveform drive and nothing else**. It receives data that is already
greyscale-reduced and already bit-packed, so every decision about how the sign looks is
made here. There is no "let the panel dither it" option.

```
grey8 -> (Beautify) -> change-detect -> rect list -> merge/limit(<=15)
      -> align to 16-bit quanta -> crop/rotate per display -> dither
      -> bit-pack 1bpp/4bpp -> per-display interlace
```

## Encodings

Two exist. Nothing else is legal anywhere in the vendor's code.

| `Encoding` | bpp | levels | output ramp | alignment quantum |
|---|---|---|---|---|
| `1` | 1 | 2 | `0`, `255` | 16 sub-pixels |
| `4` | 4 | 16 | `n * 17` | 4 sub-pixels |

* 4 bpp: the **even** pixel goes in the **low** nibble, and the nibble is the top 4 bits
  of the 8-bit grey (truncation, not rounding).
* 1 bpp: **MSB-first**, hard threshold at `>= 0x80`.
* **`stride == width`, zero row padding.** The pack runs linearly across row
  boundaries, which is why the alignment rule is on `width * height`, not on width.
  Payload is exactly `W*H/2` or `W*H/8`.

## Dithering

| value | name | notes |
|---|---|---|
| `0` | `default` | **invalid at the encoder** -- raises |
| `1` | `none` | top-nibble truncation (4 bpp) / MSB threshold (1 bpp) |
| `2` | `bayer` | **bi-level only** -- warns at 4 bpp |
| `3` | `floyd-steinberg` | error diffusion onto the uniform ramp |
| `4` | `blue-noise` | **our extension, not the vendor's** |

**`4` is safe to invent because the dithering mode never appears on the wire.** The
device gets pre-quantised bits; the number is a server-side knob and we replace the
server. `1`-`3` keep the vendor's meanings for compatibility.

### Prefer blue noise at 4 bpp

* `bayer` is bi-level: GraphicsMagick's `OrderedDitherImage()` takes no level
  parameter, so a 4 bpp bayer rectangle throws away 14 of the 16 greys the panel can
  show. We reproduce that (with a warning) rather than silently invent a 16-level
  "bayer". Pass `dither_levels=16` to opt into a multi-level ordered dither.
* `floyd-steinberg` is **spatially unstable**. Error diffuses across the rest of the
  image, so a one-word text change dirties far more than the edit. Measured on a
  256x256 test image with a 16x16 (256 px) edit:

  | mode | dirty pixels | dirty bounding box |
  |---|---|---|
  | `none` | 256 | 256 |
  | `bayer` | 126 | 256 |
  | `blue-noise` | 256 | 256 |
  | `floyd-steinberg` | **1077** | **20592** |

  That 80x bounding-box inflation feeds straight into change detection: more
  rectangles, more pressure on the 15-region limit, more panel flashing.
* `blue-noise` gets ordered-dither stability **without** Bayer's cross-hatch. The
  64x64 matrix is generated by void-and-cluster (Ulichney, sigma 1.5, fixed seed) and
  **committed** as `data/blue_noise_64.npy`, so output is reproducible across runs and
  machines. Regenerate with `tools/gen_blue_noise.py`.

Pass `blue_noise_matrix=` to use your own matrix -- e.g. the exact one your renderer
already uses -- and get identical pixels on both sides.

### Ordered dithers tile in canvas coordinates

`none`, `bayer` and `blue-noise` are pixel-local, so they are applied once over the
whole session canvas with the matrix phased on the **absolute** canvas coordinate. Two
partial updates that abut therefore produce exactly the pixels one combined update
would have -- no seam. `floyd-steinberg` cannot work that way and is run per rectangle
in display-local space, which is where the vendor runs it.

### If your renderer already dithered

Use `dithering=1` (`none`). It is a bit-for-bit identity on content already on the
`n * 17` ramp, because `(n * 17) >> 4 == n`. That is how the live session is driven.

## The 32" sign

The device has **two physical 2880x640 channels**; the server models **four logical
1440x640 displays stacked vertically** (canvas 1440x2560) and folds them back into two
on the wire by interleaving each pair at **4-pixel granularity**.

```
ScreenID 0  <-  interlace(band 0, band 1)
ScreenID 1  <-  interlace(band 3, band 2)     <-- lanes SWAPPED
```

The driver is `eink-flip`: each 1440-wide band is **horizontally mirrored** before
packing. Get the mirror or the swap wrong and the sign shows a mirrored or scrambled
image. Both are verified byte-exactly against captured traffic.

Consequence: **every push `encode_frame` produces for this hardware is full-screen.**
`getRectangleSupport` returns false unconditionally for it, and the interlacer needs all
four full-size rectangles, so a partial rectangle in *canvas* coordinates cannot be sent.
`encode_frame` enforces this (`Panel.forces_full_screen`).

The device is not the limit, though. A rectangle addressed in **screen** coordinates
never enters the fold, and the sign accepts those: measured on 2026-10-05, acked, drawn
only where addressed, checksum echoed back. There is no screen-space encoder here yet —
see `OPEN-QUESTIONS.md` A10 for what one needs to do.

## The state checksum

`ImageHeader.Checksum` is **XXHash32, seed 0, over the raw 8-bit state image**, with a
result of `0` remapped to `1`. It is *not* a CRC (transport checksums are CRC-32/IEEE)
and *not* over the encoded data.

The device stores the tag of the last image it applied and echoes it as
`DisplayStateCRC`. Send `frame.state_checksum` in every `ImagePacket` and keep
`frame.state` for the next call. A mismatch costs one redundant full-screen redraw --
a quality bug, not a hard failure.

`xxhash` (a core dependency) is used when importable; a pure-Python XXH32 is included
so `imaging/` works without it, and the test suite checks the two against each other.

## Inverse (ghost-clearing) updates

`encode_frame(..., inverse=True)` **clears** `RectangleHeader.Options` bit `0x0002` on
every rectangle of one full-screen frame. Clear means inverse; set means an ordinary
update.

**Verified on hardware**, by A/B on the live sign: `options=0` makes the firmware log
`inv: 1` and `Force Inverse and full area update`, `options=2` makes it log `inv: 0` with
no such line (`ImgOpt=0x00003024` against `0x00000124`). The vendor's admin UI writes the
same key from its "Inverse updates" dropdown, where `0` is "Enable" and `2` is "Disable".

So with the vendor's shipped `RectangleFlags = 0` the bit is **already clear and every
full-screen push inverts.** `inverse=True` is therefore a no-op on a default
configuration; pass `rect_options` with bit 1 set to get ordinary updates, and clear it
again for the pushes you want inverted.

## What is verified against real device bytes

`tests/imaging/test_golden_capture.py` replays the 1.84 MB image push captured from the
live sign and reproduces **both 2880x640 payloads byte-for-byte** plus
`ImageHeader.Checksum == 3741864387` -- the value the device itself echoed back. One
test pins down the nibble order, the ramp, the linear packing, the interlace
granularity, the screen-1 lane swap, the mirror, the band order and the hash at once.

Not verified against hardware: display rotations 1/2/3 (self-consistency only, our sign
runs rotation 0), interlacing mode 1 (hardware revision 1.0.0 -- raises rather than
guess), colour-mask drivers (not implemented), and `Beautify`'s exact shift term.

**Not bit-exact to GraphicsMagick**, and not claimed to be: `bayer`'s matrix and
`floyd-steinberg`'s error weights are our own. GM's `QuantizeImage` also derives its
16-colour palette from the image histogram, which the packer then truncates to nibbles;
we quantise to the uniform ramp the wire format actually carries. No GM output was
available to diff against.
